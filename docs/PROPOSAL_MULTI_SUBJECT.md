# 提案 · 多主体候选拆分（连通域后处理）— 仅方案，未写代码

> R5 · 规格「多主体实例分割」为产品增强，规格外功能，需确认范围后再授权实现。
> 本文只做方案设计，**未改任何 src 代码**。若采纳，下一轮单独授权实现。

## 一、目标与非目标

**目标**：同一张显著性图（u2net 单输出）拆出多个 `SubjectCandidate`，让现有
UI（K2 主体选择已支持多候选展示）真正拿到 >1 个候选。

**明确非目标**：

- **这不是实例分割模型**，只是对显著性图的后处理。u2net 家族不做实例区分，
  拆分结果无法回答「这是不是同一个物体」，只能回答「这里有一团前景」。
- 不引入任何云 API / 新模型栈（无 YOLO / SAM）；不新增网络请求。
- 不改 C1 `Mask` / `SubjectCandidate` 契约、C4 分割管线与 C6 `detectSubjects()`
  的对外签名。

## 二、可行性：现有 Mask 契约下能做

`SubjectMask.data` 是 0–255 前景置信度图（`threshold` 默认 128）。
在二值化后的前景图上跑连通域，每个域生成一个候选，契约字段完全够用：

| SubjectCandidate 字段 | 连通域拆分下的取值 |
| --------------------- | ------------------ |
| `mask`                | 全尺寸蒙版，仅该域内保留前景置信度，域外置 0（或共享大蒙版 + thumbnail，见「存储」） |
| `bbox`                | 该域的最小包围盒（复用 C2 `effectiveBBox` 逻辑） |
| `confidence`          | 该域内前景置信度均值（0–1），不是模型置信度，需在 UI 文案中说明 |
| `label`               | 沿用 `SUBJECT_LABEL_MAIN`，可加 `cc-split` 后缀说明来源 |

拆分必须发生在 **C2 后处理之后**（去噪 → 填孔 → 拆域），否则噪点直接变成碎候选；
羽化改为按域执行，避免相邻域互相渗透。

## 三、算法与参数

```
binarize(data, threshold=128)
connectedComponents(8-邻域)            # C2 已有同款邻域约定
filter: area >= minArea
rank:   按 area 降序，取前 maxCandidates
emit:   每域一个 SubjectCandidate；无域 → 维持现状单候选
```

建议参数（实现时以验收用例校准，全部可配置）：

- `threshold`：128，沿用 `SubjectMask.threshold`。
- `minArea`：`max(256 px, 1.5% × 图像面积)`。低于此面积的域丢弃，抗背景碎块。
- `maxCandidates`：8。u2net 显著性图通常 1–3 个真实团块，8 已宽松。
- 域合并间隙（可选，二阶段）：对小于 `dilateGap`（建议 4 px）的域间间隙膨胀合并，
  缓解同一主体被细缝拆散。

计算量：一次 O(n) DFS / BFS，2000×2000 图约几毫秒级，Worker 内执行不影响 UI。

## 四、风险

1. **背景碎块被当成主体**（最大风险）：显著性图对纹理背景（树影、花纹）常出
   低置信度碎块。缓解：`minArea` + 域内平均置信度二次门槛（建议 ≥ 0.6）+
   UI 保持「默认选最大域」，碎候选仅展示不自动选中。
2. **同一主体被拆散**：主体内部置信度低谷（反光、遮挡）会被切成多块。
   缓解：`dilateGap` 合并；两阶段合并失败时退回单候选（宁少勿碎）。
3. **相邻主体粘连**：两个物体在显著性图上融合成一个域——本方案无能力分开，
   这是与真实例分割的本质差距，需在文档与 UI 提示中如实说明。
4. **存储放大**：N 个候选 × 全尺寸蒙版 Blob。缓解：候选蒙版可存「域内 bbox
   裁剪 + 全尺寸尺寸标注」或共享原始蒙版引用；实现时按 C1 现有 Blob 存储评估。
5. **确定性**：连通域遍历顺序固定（行优先 + 固定邻域序），输出顺序按面积降序、
   同面积按最小索引升序，保证同图同参同结果（沿用 C3 确定性约定）。

## 五、验收用例（实现后必须通过）

| # | 图构造 | 期望候选数 | 断言要点 |
| --- | ------ | ---------- | -------- |
| 1 | 640×640 白底，左上与右下各一个 128×128 纯黑实心方块（间隔 ≥ 200 px） | 2 | 两域 bbox 互不重叠；置信度均 ≈ 1；顺序按面积（同面积按索引） |
| 2 | 640×640 白底，单主体居中 256×256 黑块，背景加 3 处 16×16 灰色碎块（亮度接近背景） | 1 | 碎块低于 minArea / 置信度门槛被过滤；不产生背景候选 |
| 3 | 640×640 白底，一个 320×320 黑块内部含 64×64 白色缺口（模拟反光）且缺口 < dilateGap 可合并 | 1 | 缺口不把主体拆成两个候选（或合并后归一） |

用例 2 同时是红线：**宁缺勿滥**——过滤过强导致漏检可接受（用户仍可手绘蒙版），
把背景当主体不可接受。
