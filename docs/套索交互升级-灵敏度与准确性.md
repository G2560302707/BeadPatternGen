# 套索升级 1.4：灵敏度 × 准确性

> 2026-10-25 · 目标：解决「圈住的豆选不上」「橡皮筋跟不上手」「手一快选区就缺块」三个套索痛点。
> 现状代码：`src/core/pattern/selection.ts`（光栅化）+ `src/features/pattern-preview/PatternBoard.tsx`（交互）。

## 问题定位（现状，均已核实到行）

### 准确性

1. **起点吸附格心**：`PatternBoard.tsx:869` 起笔点记为 `hit.x + 0.5, hit.y + 0.5`（格子中心），
   而不是指针真实位置。起笔即偏差最多半格，贴边圈选时第一笔就是歪的。
2. **格心判定丢边界格**：`selection.ts:69` 只测格心 `(x+0.5, y+0.5)` 是否在多边形内。
   贴着主体边缘圈一圈，凡格心压线的边界豆全部落选——「明明圈住了却没选上」的主因。
   小于 1 格的圈更是一格都选不中。
3. **预览与提交规则不一致（自交空洞）**：拖拽中橡皮筋填充走 canvas 默认 **nonzero** 规则
   （`PatternBoard.tsx:193-197`），提交走 `pointInPolygon` 的 **even-odd** 规则。
   笔迹自交/回笔时，拖拽中看到的是实心，松手却出空洞——「松手缺一块」。
4. **画布外不能起笔**：`PatternBoard.tsx:839-848` `if (!hit) return;` 先于 `setPointerCapture`。
   主体贴着图纸边缘时，自然的「从边缘外起笔圈过去」手势直接无效。
5. **快速划动丢采样**：指针事件按帧合并，一帧内的真实轨迹被丢弃；
   `appendLassoPoint` 的 0.5 格线性插值只救直线段，救不了快甩时的弧线切角。

### 灵敏度

6. **每个 move 事件全量 setState + 全量重绘**：`PatternBoard.tsx:913-914` 每次 pointermove 都
   `setSelection(lassoIndices(...))` → zustand 通知 → 组件重渲染 + `useLayoutEffect` 重跑
   `paintPattern`（重画**每一颗豆**）+ 选区逐格 `fillRect`。100×100 图纸、120Hz 指针下
   每秒上万次 fillRect，橡皮筋必然掉帧——「跟不上手」的主因。
7. **无 rAF 合帧**：同一帧内多个 move 事件各触发一次全量重绘。
8. **每次 move 调 `getBoundingClientRect()`**：布局抖动，雪上加霜。
9. **没有 pointercancel 处理**：笔/触摸被系统手势接管、或 pointerup 丢失时，
   `strokeRef` 卡在 true——套索进入「幽灵跟手」（没按键也一直在画）。这是「有问题」的隐藏来源之一。

### 交互缺口

10. **触摸设备不可用**：`.pattern-stage` 没有 `touch-action: none`，触摸拖动被浏览器滚动手势吃掉。
11. **Esc 不能取消进行中的圈选**（只能事后清空）。
12. **没有闭合预示**：看不到最后一笔会怎么连回起点。

## 升级设计

### 1. 光栅化重写：多扫描线覆盖率 ≥ 50%（selection.ts）

替换「逐格格心 pointInPolygon」为**扫描线 + 子扫描线覆盖率**：

```
rasterizeLasso(ring, width, height, K = 4):
  bbox = clamp(环的包围盒)
  for y in bbox 各行:
    coverage[] 清零
    for k in 0..K-1:                       # 子扫描线 y+0.125 / 0.375 / 0.625 / 0.875
      sy = y + (k + 0.5) / K
      交点 = 环上各边与 sy 的交点（半开区间边规则去重顶点；水平边跳过），按 x 排序
      # nonzero：交叉带方向（上→下 +1，下→上 -1），winding ≠ 0 的 x 区间为内部
      for 每个内部区间 [xa, xb]:
        for x in floor(xa) .. ceil(xb)-1:
          coverage[x] += min(xb, x+1) - max(xa, x)    # 与该格的水平重叠长度
  选中 = coverage / K ≥ LASSO_COVERAGE_THRESHOLD (0.5)
```

- **面积归属**：大半格在圈内就选中，边界豆不再丢；不足 1 格的小圈也能选中覆盖最多的那一格。
- **nonzero 规则**：与拖拽预览（canvas 默认填充）天然一致，自交空洞消失；回笔（A→B→A）不选，
  八字自交两叶都选——比 even-odd 宽容且所见即所得。
- **性能**：O(扫描线 × E + 覆盖格数)，典型环 E≈200-600、区域几十×几十格 → **亚毫秒**，
  可以每帧实时跑（供拖拽中的格级实时预览）。逐格 3×3 超采样点判定被否：O(格数×9×E)，
  大圈每帧不可行，且是点采样不是面积。
- **签名不变**：`lassoIndices(points, width, height): number[]`；新增导出
  `LASSO_COVERAGE_THRESHOLD = 0.5`。`pointInPolygon` 仅测试还引用则一并清理。

### 2. 拖拽期零 React 状态（PatternBoard.tsx）

把「拖拽中」从 React 渲染循环里完全摘出来，改为快照 + 命令式绘制：

- **pointerdown（套索）**：
  - 无条件 `setPointerCapture`（不再要求命中画布内）；
  - 缓存 stage rect 到 ref（ResizeObserver 回调里失效）；
  - 把当前画布快照进离屏 canvas；
  - 记录**精确格坐标**（`(clientX - rect.left - offsetX) / scale`，不吸附格心）；
  - 不再 `setSelection([hit.index])`——按下时无任何选区变化。
- **pointermove（套索）**：
  - `event.getCoalescedEvents?.() ?? [event]` 逐**原始采样**喂 `appendLassoPoint`
    （救回帧间被合并的轨迹，快速甩动保真）；
  - rAF 合帧绘制：`drawImage(快照)` → 橡皮筋（实线路径 + 起点虚线回连 + nonzero 半透明填充）
    → 叠加覆盖率光栅化的格级预览（亚毫秒，所见即所得）；
  - **零 setState、零 store 写入**。
- **pointerup**：先光栅化 → `setSelection(indices)` 一次性提交 → 释放快照（先算后清 lassoRef）。
- **pointercancel / onLostPointerCapture 兜底**：丢弃本次圈选，清理 `strokeRef` 等全部拖拽态，
  根除幽灵跟手。
- **退化路径**：累计路径长 < 0.7 格或光栅化为空 → 视为点击 → 清空选区（见决策点 D1）。

### 3. 交互补齐

- **Esc**：拖拽中 = 取消本次圈选（不提交、保留原选区）；非拖拽 = 清选区（现状不变）。
- **CSS**：`.pattern-stage { touch-action: none; }`（见决策点 D4）。
- **闭合预示**：虚线从当前点连回起点，一眼看出松手后的闭合形状。
- **框选顺手受益**：rect 缓存 + rAF 合帧同样适用于 select-rect 的 move 路径（小改动，同批做）；
  select-rect 仍要求画布内起笔（矩形本身有边界语义，不强改）。

### 4. 拖拽前后开销对比

| 环节 | 现状（每次 move） | 升级后（每帧至多一次） |
| --- | --- | --- |
| getBoundingClientRect | 每次 | 拖拽开始时一次 |
| 轨迹采样 | 帧合并后的粗采样 | 逐原始采样（coalesced） |
| 光栅化 | 逐格格心 O(格×E) | 扫描线 O(E)，亚毫秒 |
| React/store | setSelection → 全组件重渲染 | **0 次**（up 时 1 次） |
| 重绘 | paintPattern 全量重画所有豆 | 1 次 drawImage 快照 + 路径 |

## 参数一览

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `LASSO_COVERAGE_THRESHOLD` | 0.5 | 格面积过半即选中，可调 |
| 子扫描线数 K | 4 | 精度/开销平衡点，内部常量 |
| `LASSO_POINT_SPACING` | 0.5（不变） | 插值步长 |
| 退化路径阈值 | 0.7 格累计长度 | 小于此视为点击 |
| 橡皮筋样式 | 实线路径 + 虚线回连 + 15% 填充 | 与现有视觉一致，多一条回连虚线 |

## 决策点（默认按推荐执行）

- **D1 纯点击行为**：推荐**清空选区**（符合圈选心智，白送一个快速取消手势）；
  现状是选中单格（「只是点了一下怎么选了一格」的困惑源）。无测试依赖现状。
- **D2 自交规则**：推荐 **nonzero**（与预览一致、回笔宽容）；even-odd 是 Windows 圈选风格但会出空洞。
- **D3 覆盖率阈值**：0.5（面积过半）。
- **D4 touch-action: none**：推荐对 `.pattern-stage` 常开（滚轮在该区域本来就是缩放，语义一致）。

## 测试与验收

**单测（selection.test.ts 重写套索部分）**

- 骑线格归属：多半格在内 → 选；少半格 → 不选（阈值边界）。
- 八字自交：两叶都选中（nonzero）；回笔 A→B→A：全不选。
- 小于 1 格的圈：选中覆盖最多的 1 格（旧实现选 0 格）。
- 出界环：整圈在画布外 → 空；部分出界 → 只裁剪内侧。
- 大而光滑的圈：与旧格心实现差异仅限边界一圈（等价性抽样）。

**e2e（interaction.spec.ts）**

- 现有「快速划圈不缺块」测试必须保持通过（Playwright 离散事件无 coalesced，正好覆盖 fallback 分支）。
- 新增：从画布外起笔圈选（改造前必挂、后通过）。
- 新增：Esc 拖拽中取消（选区保持原样）。
- pointercancel 无法可靠 e2e，走代码审查 + 手测（DevTools 触发 `pointercancel` 事件）。

**性能验收（手测 + 埋点）**

- 拖拽全程 React 渲染次数 = 0（DevTools Profiler 验证）。
- 100×100 图纸拖拽重绘 ≤ 2ms/帧（performance.now 埋点，临时代码，验完删）。

**回归门禁**：`pnpm test`、`pnpm test:e2e`、`pnpm lint`、`pnpm typecheck`、`pnpm quality:run` 全绿。
