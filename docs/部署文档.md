# 部署文档 · 豆豆图纸（BeadPatternGen）

> 适用版本：`0.2.0`。产品形态是**纯前端静态站**：没有后端、数据库、账号体系，也没有运行时环境变量。图片与计算全部留在浏览器本地。
>
> 配套文件：[deploy/nginx.conf](../deploy/nginx.conf)、[deploy/Dockerfile](../deploy/Dockerfile)、[deploy/docker-compose.yml](../deploy/docker-compose.yml)、[deploy/Caddyfile](../deploy/Caddyfile)、[deploy/_headers](../deploy/_headers)、[deploy/vercel.json](../deploy/vercel.json)、[scripts/check-deployment.mjs](../scripts/check-deployment.mjs)。

---

## 0. 一句话结论

```bash
pnpm install --frozen-lockfile
pnpm models:download          # 约 386 MB，四个分割模型
pnpm build                    # 产物在 dist/
```

把 `dist/` 原样交给静态服务器，并保证四件事：

1. HTML 响应带 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`；
2. 全站 HTTPS（`localhost` 除外）；
3. `.mjs` 返回 JavaScript MIME、`.wasm` 返回 `application/wasm`；
4. `/models/`、`/ort/` 缺失时返回真实 404，**不能**被 SPA 回退成 `index.html`。

服务器只做「发文件 + 发响应头」，不参与任何计算。

---

## 1. 应用结构（部署视角）

```text
浏览器
├─ 主线程   React SPA（HashRouter，URL 形如 /#/make/import）
├─ Worker   生成算法 / 分割推理（onnxruntime-web，WASM，可选 WebGPU）
└─ 本地存储 IndexedDB（工程 / 图纸 / 缩略图）
           Cache Storage（分割模型，桶名 bead-pattern-segmentation-models-v1）

静态服务器
└─ dist/   index.html + assets + fonts + samples + ort + models
```

几个直接后果：

- **路由无需 rewrite**：使用 `HashRouter`，`#` 之后的部分不会发给服务器；`try_files` 回退只是兜底。
- **不做服务端渲染 / 不做 API 代理**：没有 `/api`，也没有上传接口。
- **构建期配置**：模型清单、`base`、WebGPU 开关都在构建时固化。同一份产物可以部署到多个域名，但改配置必须重新构建。
- **数据绑定域名**：IndexedDB 按 origin 隔离。上线后再换域名（含 http→https、www 与非 www），老用户的作品库不会自动迁移。

## 2. 部署前必须知道的约束

| # | 约束 | 原因 | 不满足的后果 |
| - | --- | --- | --- |
| 1 | 配置 COOP + COEP | 开启 `crossOriginIsolated`，才能用 `SharedArrayBuffer` | 功能可用，但分割退回**单线程 WASM**，首次识别明显变慢 |
| 2 | 必须 HTTPS（内网也要） | Cache Storage、`crypto.subtle`、WebGPU、`SharedArrayBuffer` 都要求安全上下文 | 模型**每次访问都重新下载**、SHA-256 校验被跳过；分割单线程 |
| 3 | 资源同源 | `COEP: require-corp` 会拦截没有 CORP 头的跨源资源 | 外站字体 / 图片 / 统计脚本被拦截（本项目本身零外链） |
| 4 | 模型体积大 | 单个模型 4.4–171 MB，合计约 386 MB；`dist/` 约 443 MB | 平台单文件上限、镜像大小、CDN 回源与流量成本 |
| 5 | MIME 正确 | `.mjs` 要按 JS 解析，`.wasm` 要按 `application/wasm` 实例化 | ORT 动态导入失败 / WebAssembly 编译失败 |
| 6 | 模型与 `ort` 目录必须真实存在 | 构建时 `pnpm models:download`、`pnpm ort:sync` 生成，二者默认不入库 | 抠图报 `E_MODEL_LOAD_FAILED`；ORT 初始化失败 |

> 第 1、2 条只影响**主体识别（抠图）**的性能与缓存；导入、裁剪、生成、精修、导出等核心流程不依赖它们。即便如此，生产环境仍建议全部满足。

## 3. 构建

### 3.1 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | `^20.19.0` 或 `>=22.12.0`（Vite 8 的 engines）；建议 **Node 22 LTS**，本项目在 22.22 验证 |
| pnpm | 10 及以上（lockfile v9；本地用 pnpm 12.14 验证） |
| 磁盘 | 至少 2.5 GB 空闲（`node_modules` + 约 443 MB 产物 + 下载临时文件） |
| 网络 | npm registry 可访问；`pnpm models:download` 需要访问 GitHub Releases（约 386 MB） |
| 操作系统 | Linux / macOS / Windows 均可构建；容器构建建议 Linux |

> 构建依赖 `devDependencies`（`vite`、`typescript` 等）。不要用 `pnpm install --prod`，也不要设置 `NODE_ENV=production` 后再构建。

### 3.2 标准步骤

```bash
git clone <repo> BeadPatternGen
cd BeadPatternGen

pnpm install --frozen-lockfile
pnpm models:download      # 下载并校验 4 个 ONNX 模型；可重复执行，已就绪会跳过
pnpm build                # prebuild 自动执行 pnpm ort:sync；然后 tsc + vite build
```

`pnpm build` 实际做三件事：

1. `prebuild` → `pnpm ort:sync`：把 `onnxruntime-web` 的 `.wasm/.mjs` 复制到 `public/ort/`；
2. `tsc --noEmit -p tsconfig.app.json`：类型检查，**失败即终止构建**；
3. `vite build`：输出到 `dist/`（包含 `public/` 下的模型、字体、示例图）。

### 3.3 产物清单

| 路径 | 体积（约） | 说明 |
| --- | --- | --- |
| `dist/index.html` | 2 KB | 入口；不缓存，发布后立即生效 |
| `dist/assets/` | 30 MB | 带哈希的 JS/CSS/Worker；其中含一份 28 MB 的 ORT wasm 资源 |
| `dist/ort/` | 28 MB | 运行时实际使用的 ORT wasm + mjs（路径由 `BASE_URL` 拼接） |
| `dist/models/` | 385 MB | 四个 ONNX 模型；缺失时抠图不可用 |
| `dist/fonts/` | 1.6 MB | 自托管字体子集 + PDF 中文字体 |
| `dist/samples/` | 20 KB | 内置示例图 |
| **合计** | **约 443 MB** | 每次发布都要准备这么大的目录 |

模型明细（`src/core/subject/segmentation/model-manifest.json`）：

| 模型 | 体积 | 定位 |
| --- | --- | --- |
| `isnet-anime` | 168 MB | **默认**，二次元 / 人物 |
| `isnet-general-use` | 170 MB | 通用 |
| `silueta` | 42 MB | 通用轻量 |
| `u2netp` | 4.4 MB | 最快，质量较低 |

### 3.4 模型裁剪与流量

四个模型都会出现在抠图面板的模型下拉框中。如果只部署一部分：

- **必须保留默认模型**（当前是 `isnet-anime`），否则首次抠图就失败；
- 其余模型被选中时会提示模型下载失败（HTTP 404），不影响其他功能；
- 只保留部分文件时，可在 `public/models/` 放需要的 `.onnx` 后再构建，不必执行完整的 `models:download`。

**流量提醒**：默认模型 168 MB。用户第一次点「主体识别」会下载它（之后进 Cache Storage，不再重复下载）。如果预期有大量轻度用户，建议把 `model-manifest.json` 的 `defaultModelId` 改为 `u2netp`（4.4 MB）后重新构建，把高精度模型留给用户手动选择。这是质量与带宽的取舍，不是部署硬要求。

### 3.5 部署到子路径（如 `https://example.com/bead/`）

默认 `base` 是 `/`。要部署到子路径，**必须在构建时改 base**，否则所有 `/assets/...` 都会 404：

```ts
// vite.config.ts
export default defineConfig({
  base: "/bead/",
  // ...
});
```

然后：

- `pnpm build`；
- 把 `dist/` 放到 Web 根目录下的 `bead/`；
- 服务器把 `/bead/` 映射到该目录（nginx 示例见 [deploy/nginx.conf](../deploy/nginx.conf) 末尾注释）。

应用内所有资源路径都走 `import.meta.env.BASE_URL`（模型、ORT、示例图、PDF 中文字体），Vite 会自动改写 `index.html` 里的 `/favicon.svg` 与 `/assets/...`。

> **Windows Git Bash 坑**：命令行的 `--base=/bead/` 会被 MSYS 转成 Windows 路径（例如 `D:/App/Git/bead/`），导致构建出错误前缀。用 `MSYS_NO_PATHCONV=1 pnpm exec vite build --base=/bead/`，或直接改 `vite.config.ts`。

### 3.6 构建期开关

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| `base` | `/` | 部署根路径 |
| `VITE_SEGMENTATION_WEBGPU=1` | 关闭 | 允许分割优先尝试 WebGPU，失败自动回退 WASM。默认关闭更稳；开启后需在目标浏览器实测 |

没有其他运行时环境变量。不要指望在容器启动时改端口 / API 地址——本项目没有这些。

### 3.7 模型下载失败怎么办

`pnpm models:download` 会按清单里的 `byteLength` + `sha256` 校验，坏文件不会写入。若 GitHub 不可达：

1. 按 `model-manifest.json` 里的 `sourceUrl` 在可联网机器下载；
2. 校验 SHA-256 与大小；
3. 放到 `public/models/`，文件名保持一致；
4. 重新 `pnpm build`；运行时会再次校验，校验不过会拒绝加载并清除缓存。

构建前可快速确认：

```bash
ls -lh public/models/*.onnx
ls -lh public/ort/
```

## 4. 响应头、MIME、缓存与压缩

### 4.1 必需响应头

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
X-Content-Type-Options: nosniff
```

验证方式：部署后打开 DevTools Console：

```js
crossOriginIsolated   // 期望 true
```

`true` 时 `configureOrt()` 会把 `numThreads` 设为 `min(4, CPU 核数)`；`false` 时固定为 1。

注意：

- 两个头必须出现在 **HTML 文档响应**上；只给静态资源加没有意义。
- `Cross-Origin-Embedder-Policy` 用 `require-corp`，**不要用 `credentialless`**：后者不会让 `crossOriginIsolated` 变为 `true`。
- 如果前面有 CDN / 反向代理 / 云 WAF，确认它们**不会剥离**这两个头。
- `COEP: require-corp` 会拦截所有没有 CORP/CORS 的跨源子资源。本项目零外链，所以没有影响；将来加统计、外链字体、外链图片时要一并处理。
- `COOP: same-origin` 会切断 `window.opener` 与跨源弹窗通信。本项目不依赖这些能力。

### 4.2 MIME 类型

| 扩展名 | 正确 Content-Type | 配错的典型报错 |
| --- | --- | --- |
| `.mjs` | `text/javascript`（或 `application/javascript`） | `Failed to fetch dynamically imported module` |
| `.wasm` | `application/wasm` | `WebAssembly.instantiate(): ...` / `Incorrect response MIME type` |
| `.js` | `text/javascript` 或 `application/javascript` | 入口脚本被拒绝执行 |
| `.onnx` | `application/octet-stream`（默认即可） | 一般无影响；重点是不要返回 HTML |
| `.woff2` / `.ttf` | `font/woff2` / `font/ttf` | PDF 中文页眉回退英文 |
| `.svg` | `image/svg+xml` | 图标不显示 |

nginx 较新版本的 `mime.types` 已包含 `.wasm` / `.mjs`；旧发行版可能没有。示例配置用 `default_type` 兜底，不会覆盖已正确映射的类型。

### 4.3 缓存策略

| 路径 | 建议 Cache-Control | 原因 |
| --- | --- | --- |
| `/index.html`、`/` | `no-cache` | 每次发布立即可见；文件很小 |
| `/assets/*` | `public, max-age=31536000, immutable` | 文件名带内容哈希 |
| `/models/*.onnx` | `public, max-age=2592000`（30 天） | 内容固定；运行时另有 SHA-256 校验 |
| `/ort/*` | `public, max-age=2592000` | 文件名不随内容变化，升级 ORT 时要清缓存 |
| `/fonts/*`、`/samples/*` | `public, max-age=2592000` | 长期稳定 |

模型更新注意：模型文件名固定（如 `isnet-anime.onnx`），若替换内容而不改名：

- 浏览器 HTTP 缓存可能仍返回旧文件；
- 应用运行时 SHA-256 校验会发现不匹配并删除 Cache Storage 中的副本，但下一次请求仍可能拿到旧 HTTP 缓存，表现为持续报错。

**升级模型时请改文件名并同步 `model-manifest.json`**，或让 CDN/浏览器缓存过期后再发版。

### 4.4 压缩

- 压缩：HTML、CSS、JS、JSON、SVG、字体；wasm 可选（收益有限）。
- **不要压缩 `.onnx`**：体积大、已经是稠密二进制，在线 gzip 会持续占用 CPU，收益接近零。
- nginx 示例只把文本类加入 `gzip_types`；`.onnx` 默认不压。
- 高流量站点可用 Brotli 预压缩（`gzip_static` / `brotli_static`），但不要把 168 MB 模型放进每次构建的压缩流程。

## 5. 方案 A：nginx（推荐，自有服务器）

### 5.1 纯静态部署

```bash
# 1. 构建
pnpm install --frozen-lockfile
pnpm models:download
pnpm build

# 2. 同步产物（首次）
sudo mkdir -p /var/www/bead
sudo rsync -a --delete dist/ /var/www/bead/
sudo chmod -R a+rX /var/www/bead

# 3. 安装站点配置
#    若系统自带默认站点（/etc/nginx/sites-enabled/default 或 conf.d/default.conf），
#    先移除它，避免两个 server 抢 80 端口。
sudo cp deploy/nginx.conf /etc/nginx/conf.d/bead.conf
sudo nginx -t
sudo systemctl reload nginx

# 4. HTTPS（推荐 certbot 自动改写）
sudo certbot --nginx -d example.com
```

浏览器访问 `https://example.com/`，然后跑验收脚本（见第 10 节）。

> SELinux 发行版（CentOS / RHEL / Fedora）如出现 403：
> `sudo chcon -R -t httpd_sys_content_t /var/www/bead`。

### 5.2 配置要点

完整配置见 [deploy/nginx.conf](../deploy/nginx.conf)，几个容易踩的点已在文件里注释：

- **`add_header` 继承**：在 `location` 里再写 `add_header` 会覆盖 `server` 级继承的头。示例中静态资源 location 只重复 `nosniff`，不重复 COOP/COEP（它们只对 HTML 文档有意义）；首页 `location /` 没有 `add_header`，因此继承 COOP/COEP。
- **`/models/` 与 `/ort/` 用 `try_files $uri =404`**：避免 SPA 回退把缺失模型变成 200 HTML。
- **`/assets/` 用 1 年缓存**：文件名带哈希，可安全 immutable。
- **首页 `expires -1`**：等价于 `Cache-Control: no-cache`，且不会触发 `add_header` 覆盖问题。

### 5.3 子路径

按 3.5 重新构建后，把配置里的：

```nginx
root /var/www/bead;
```

改为 `root /var/www;`（目录仍是 `/var/www/bead/`），并把入口 location 改为：

```nginx
location /bead/ {
    expires -1;
    try_files $uri $uri/ /bead/index.html;
}
```

其余 `/assets/`、`/models/`、`/ort/` 前缀也要相应加 `/bead/`，或整体放进 `location /bead/ { ... }` 内。

### 5.4 常见运维

```bash
nginx -t                          # 改配置后先测语法
systemctl reload nginx            # 平滑重载
tail -f /var/log/nginx/access.log # 排查 404 / MIME / 大文件请求
```

日志里能看到的只有静态资源请求，**没有用户图片**——图片不上传。

## 6. 方案 B：Docker / Docker Compose

配套文件：[deploy/Dockerfile](../deploy/Dockerfile)、[deploy/docker-compose.yml](../deploy/docker-compose.yml)、[.dockerignore](../.dockerignore)。

### 6.1 构建与运行

```bash
# 在仓库根目录
docker build -f deploy/Dockerfile -t bead-pattern-gen:0.2.0 .

docker run -d --name bead \
  -p 8080:80 \
  --restart unless-stopped \
  bead-pattern-gen:0.2.0

curl -I http://127.0.0.1:8080/
```

或：

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

镜像内是 `nginx:stable-alpine` + `/var/www/bead`，响应头配置就是 [deploy/nginx.conf](../deploy/nginx.conf)。

### 6.2 体积与模型

- 默认在镜像构建阶段执行 `pnpm models:download`，镜像约 **500 MB**（模型 386 MB + ORT + nginx）。
- 想瘦身：

```bash
docker build -f deploy/Dockerfile \
  --build-arg DOWNLOAD_MODELS=false \
  -t bead-pattern-gen:lean .
```

运行时把模型挂进容器（compose 里有注释示例）：

```yaml
volumes:
  - ./public/models:/var/www/bead/models:ro
```

否则抠图会报模型下载失败，其余功能正常。

- 构建时间主要花在 `pnpm install` 与 386 MB 模型下载上。GitHub 不通时，用 `DOWNLOAD_MODELS=false` 构建 + 挂载本地模型。

### 6.3 生产前置 HTTPS

容器只监听 80。生产环境在前面加一层 TLS 终止（Caddy / Traefik / 云负载均衡 / 宿主机 nginx），并确保：

- 转发时保留 `Host`；
- **不要剥离** COOP/COEP；
- 如果反向代理自己也加同名头，只保留一处，避免重复头导致排查困难。

## 8. 方案 D：静态托管平台

### 8.1 通用步骤

1. 构建命令：`pnpm models:download && pnpm build`（或 CI 先下载模型）；
2. 发布目录：`dist`；
3. 把 [deploy/_headers](../deploy/_headers) 复制到 `dist/_headers`（Netlify / Cloudflare Pages）；
4. 部署后用第 10 节脚本验收。

```bash
pnpm build
cp deploy/_headers dist/_headers
```

### 8.2 平台对比

| 平台 | COOP/COEP | 大文件 | 结论 |
| --- | --- | --- | --- |
| 自有 nginx | 完全可控 | 无压力 | **推荐** |
| Caddy | 完全可控 | 无压力 | 推荐 |
| Netlify | `_headers` 支持 | 先确认单文件上限；168 MB 模型可能超限 | 可用，但需确认模型能否上传 |
| Cloudflare Pages | `_headers` 支持 | 单文件上限较小（约 25 MiB，具体以平台文档为准），模型基本放不下 | 不适合直接放模型；可把模型放 R2 并同域代理（进阶） |
| Vercel | `vercel.json` 支持 | 先确认静态文件上限 | 可用性取决于平台限制；见 [deploy/vercel.json](../deploy/vercel.json) |
| GitHub Pages | **不能自定义响应头** | 单文件上限 100 MB，168/171 MB 模型放不下 | 只能做演示；分割单线程，且需裁掉大模型 |
| 对象存储 + CDN | 取决于 CDN 的自定义响应头能力 | 适合大文件 | 可行，注意同源与缓存 |

### 8.3 Cloudflare Pages / Netlify

- `_headers` 必须位于**发布根目录**（`dist/_headers`），不是仓库根目录；
- `_headers` 同时设置 COOP/COEP 与缓存策略；
- 若模型放 R2 / 对象存储，建议通过同域路径（例如 `/models/*` 的 Worker 路由或 CDN 回源）暴露，避免跨源 + COEP 带来的 CORP/CORS 配置。模型响应还需要正确的 `Content-Length`（运行时按清单校验字节数）。

### 8.4 Vercel

把 [deploy/vercel.json](../deploy/vercel.json) 复制到仓库根目录（或按 Vercel 的 Root Directory 设置），它会：

- 用 `pnpm models:download && pnpm build` 构建；
- 输出 `dist`；
- 设置 COOP/COEP 与缓存头。

模型是否会被平台接受，以当前套餐的单文件限制为准。

### 8.5 GitHub Pages

不推荐作为正式部署：

- 无法设置 COOP/COEP → 分割单线程；
- 单文件 100 MB 上限 → `isnet-anime` / `isnet-general-use` 无法上传；
- 只能保留 `u2netp`（4.4 MB）等小模型，并在 `model-manifest.json` 中把默认模型改为可用项（否则默认模型 404）。

若只是做公开演示，可以接受以上降级。

### 8.6 对象存储 + CDN（国内常用）

- 静态壳与模型放同一域名下的不同路径，避免跨源；
- 在 CDN 上配置 COOP/COEP、缓存规则与 MIME；
- 确认 CDN 不会对 `.onnx` 做转码 / 压缩 / 分片改写；
- 回源带宽与流量费用按 386 MB/版本估算，模型首次命中后由 CDN 缓存。

## 9. 内网 / 离线部署

- **构建联网，运行不联网**：在一台能访问 npm 与 GitHub 的机器上构建，把 `dist/` 拷贝到内网服务器即可。浏览器运行时只需要访问这台静态服务器。
- **内网也要 HTTPS**：用内部 CA 签发证书并让客户端信任。直接 HTTP（非 localhost）会导致模型不缓存、SHA 校验跳过、分割单线程。
- **完全离线更新**：保留 `dist/` 快照；升级 = 替换目录 + 清浏览器缓存中的 `index.html`（已配置 no-cache）。
- **不要用 `python -m http.server` / `npx serve` 做生产**：它们通常没有 COOP/COEP、正确的 `.wasm` MIME 与缓存策略。仅可用于临时预览。
- `pnpm preview` 只用于验收：它有 COOP/COEP，但没有 TLS、压缩与生产缓存策略。

## 10. 部署后验收

### 10.1 自动检查

仓库自带验收脚本（只发 HEAD/GET，不下载完整模型）：

```bash
pnpm deploy:check https://example.com/
# 或
node scripts/check-deployment.mjs https://example.com/bead/
```

检查项：

- 首页 200 且 `Content-Type: text/html`；
- COOP/COEP 是否正确（缺失记为警告；`--strict` 时视为失败）；
- 首页是否 `no-cache`；
- `index.html` 引用的 `/assets/*.js|css` 是否可访问、MIME 是否正确；
- `ort/*.wasm`、`ort/*.mjs` 的 MIME；
- 四个模型的 HTTP 状态、是否被 SPA 回退成 HTML、`Content-Length` 是否与清单一致；
- 示例图；
- 是否 HTTPS 安全上下文。

常用参数：

```bash
# 只验静态壳，跳过 386 MB 模型检查
pnpm deploy:check https://example.com/ --skip-models

# CI 中把警告也当失败（要求必须跨源隔离 + HTTPS）
pnpm deploy:check https://example.com/ --strict
```

### 10.2 手工检查

1. `curl -I https://example.com/`：确认 200、COOP/COEP、`Cache-Control: no-cache`。
2. 浏览器 Console：`crossOriginIsolated` → `true`。
3. DevTools → Network：`ort/ort-wasm-simd-threaded.jsep.wasm` 为 200 / `application/wasm`。
4. 首次抠图：`models/isnet-anime.onnx` 下载完成；DevTools → Application → Cache Storage 出现 `bead-pattern-segmentation-models-v1`；再次抠图不再发模型请求。
5. 完整流程：导入 → 抠图构图 → 裁剪 → 生成 → 精修 → 导出 PNG / PDF / CSV。
6. 刷新页面：首页作品库能恢复（IndexedDB）。
7. 导出 PDF：中文页眉正常（说明 `fonts/pindou-zh-subset.ttf` 可访问）；若变英文，检查字体 404。
8. Network 过滤第三方域：应为空（应用本身零外链；接了统计/外链字体会破坏该承诺）。
9. 子路径部署时：`/bead/favicon.svg`、`/bead/assets/*`、`/bead/models/*`、`/bead/ort/*` 全部 200。

## 11. 升级与回滚

### 11.1 静态目录发布（推荐）

```bash
sudo mkdir -p /var/www/bead-releases
sudo rsync -a --delete dist/ /var/www/bead-releases/2026-10-26/
sudo ln -sfn /var/www/bead-releases/2026-10-26 /var/www/bead
```

nginx 的 `root` 指向 `/var/www/bead`（符号链接）。发布 = 新建目录 + 切链接；回滚 = 把链接切回上一个目录。无需重启 nginx。

保留最近 2–3 个版本即可，每版约 443 MB，注意磁盘。

### 11.2 缓存与模型

- `index.html` 配 `no-cache` 是「发布立即生效」的关键；不要给它加长缓存。
- `/assets/*` 是内容哈希，可安全长期缓存。
- 模型内容变化时改文件名（并更新 `model-manifest.json`），避免旧 HTTP 缓存与新 SHA-256 冲突。
- 若必须原地替换模型，发布后提示用户强刷，或等待 30 天缓存过期。

### 11.3 CI/CD 示例（GitHub Actions）

```yaml
name: build-deploy
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm models:download
      - run: pnpm build
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist
```

产物约 443 MB，上传 / 下载都需要时间；模型下载失败时构建不会报错但产物缺模型，建议在 CI 里加：

```bash
test "$(ls dist/models/*.onnx | wc -l)" -eq 4
```

（若做了模型裁剪，改成期望数量。）

## 12. 常见问题

### Q1. 抠图报「模型下载失败：HTTP 404」

- `dist/models/` 是否包含对应 `.onnx`；
- 子路径部署是否重新构建过（`BASE_URL` 前缀）；
- nginx 是否把 `/models/` 回退成了 `index.html`（`try_files $uri =404`）；
- 文件权限 / SELinux 是否允许 nginx 读取。

### Q2. `crossOriginIsolated` 是 `false`

- HTML 响应是否同时有 COOP/COEP；
- CDN / 反代是否剥离；
- 是否只给静态资源加了头、没给 HTML 加；
- `try_files` 回退到 `index.html` 的响应是否也经过 `location /`（示例配置是）。

### Q3. 分割能跑但特别慢

先看 Console 的 `crossOriginIsolated`。为 `false` 时 `numThreads=1`，这是预期降级。补齐响应头后刷新即可。

### Q4. 控制台报 `Failed to fetch dynamically imported module`（ort `.mjs`）

通常是 `.mjs` 的 MIME 不对或 404。检查 `curl -I https://.../ort/ort-wasm-simd-threaded.jsep.mjs` 的 `Content-Type`。

### Q5. 报 `WebAssembly.instantiate(): ...` / `Incorrect response MIME type`

`.wasm` 未返回 `application/wasm`。旧 nginx 的 `mime.types` 可能缺映射；用示例配置里的 `default_type` 兜底。

### Q6. 模型第一次能加载，第二次报 SHA-256 不匹配

服务器上的模型文件变了但 URL 没变，浏览器 HTTP 缓存返回旧文件。改文件名 + 更新清单，或让缓存过期；清除站点数据可临时恢复。

### Q7. 页面能开，但导出 PDF 中文变英文

`fonts/pindou-zh-subset.ttf` 404。检查字体目录是否随 `dist/` 部署、MIME 是否可读。代码在字体加载失败时会自动回退英文，不会报错。

### Q8. 部署到子路径后白屏

八成是构建时没设置 `base`。看 `dist/index.html` 里的资源前缀是否为 `/bead/assets/...`。

### Q9. 接了统计 / 外链字体后抠图或样式异常

`COEP: require-corp` 会拦截没有 CORP 的跨源资源；同时这会破坏「零外链」的隐私承诺。若必须接，使用同源代理或带 CORP 头的资源。

### Q10. 换域名后老用户作品不见了

IndexedDB 按 origin 隔离。跨域不迁移。上线前确定最终域名与协议；如需迁移，得由用户手动导出 JSON 工程再导入。

### Q11. 能不能用 `vite preview` 直接对外？

不建议。它没有 TLS、生产级缓存与压缩配置，且是开发工具。仅用于本机验收（`http://127.0.0.1` 是安全上下文，行为与线上 HTTPS 接近）。

### Q12. 为什么 `dist/assets` 里还有一份 28 MB 的 wasm？

Vite 打包 ORT 时额外产出的资源；运行时实际通过 `BASE_URL + ort/` 加载 `dist/ort/` 下的文件。不要为了省空间手动删除 `dist/assets` 里的文件，除非你验证过构建与运行都正常。
