## 本阶段目标

把「一期做完了」变成一份可核对的证据，而不是一句自我感觉。这一阶段的产物将决定二期能不能开工。

## 产出物

- `tests/e2e/flow.spec.ts`
- `docs/PHASE1_ACCEPTANCE.md`
- `docs/KNOWN_LIMITATIONS.md`
- `docs/IMPLEMENTATION_STATUS.md（更新）`

## 验收门禁

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
```

## 提示词（先粘贴全局约束，再粘贴本段）

````text
【本阶段】S15 · 隐私审查 · E2E · 一期验收
（原文对应：原文 P6（验收） ｜ 参考工期：3–4 天 ｜ 前置：S01–S14 全部）

【只做本阶段】完成本轮后立即停止。不要顺手实现下一阶段，不要实现任何逐颗人工编辑功能
（画笔 / 橡皮 / 吸管 / 填充 / 颜色替换 / 撤销重做 / 区域编辑 / 编辑自动保存）——那属于二期，
未经我逐字说「现在授权开始二期」不得触碰。

【开工前】
1. 阅读 docs/TECHNICAL_SPEC.md 与 docs/IMPLEMENTATION_STATUS.md，缺失就说明。
2. 检查仓库真实现状，列出「准备新增 / 修改的文件清单 + 方案 + 风险 + 验收方式」，再动手。
3. 与文档冲突时先停下指出，不要擅自扩大范围。

【本轮任务】
1) 隐私审查
   - 用 Playwright 拦截所有网络请求，断言：除本站静态资源外零请求。
   - 审查代码中是否存在 fetch / axios / XMLHttpRequest / sendBeacon / WebSocket 调用，逐处说明用途（应全部为无）。
   - 页面上必须有如实的隐私说明：图片是否上传（否）、是否存入 IndexedDB（是 / 可选）、清除浏览器数据的影响。

2) E2E 主链路（Playwright）
   上传 → 裁剪 → 设参数 → 生成 → 看诊断 → 看统计 → 保存 → 刷新 → 重新打开 → 导出 PNG / PDF / CSV / JSON。
   - 必须包含取消任务用例与「旧任务不覆盖新任务」用例。

3) 一期验收表 docs/PHASE1_ACCEPTANCE.md
   对照规格 10.3 逐项给结论，每项必须有证据（测试文件 + 用例名 + 命令输出）：
   - 色卡合法率 100%：每个非空格映射到所选色卡合法颜色
   - 统计一致性 100%：sum(counts) === 非空格数
   - 保存恢复一致性 100%：矩阵、参数、色卡版本一致
   - 导出一致性 100%：导出格子与最终 Pattern 一致
   - 确定性 100%：固定输入 + 固定参数 → 相同结果
   - 视觉还原：明确标注为「人工盲测，未自动化」，不许编造分数

4) docs/KNOWN_LIMITATIONS.md
   - 如实列出：低分辨率下五官 / 小字无法表达、色卡来源的不确定性、性能边界（200×200 实测耗时）、
     浏览器兼容性、未实现的二期能力。

5) 明确写入：一期未实现人工编辑器，这是范围设定而非遗漏。

【验收门禁】以下命令必须真实执行，并粘贴原始输出（跑不了的标「未运行」+ 原因）：
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build

【交付报告】
1. 改动文件清单（新增 / 修改，一行一个，各附一句话作用）
2. 每条命令的原始输出（通过 / 失败；失败贴报错原文）
3. 未完成项与原因（没有写「无」）
4. 已知风险与我需要决策的点
5. 更新 docs/IMPLEMENTATION_STATUS.md
````

## 风险提示

这一阶段最大的诱惑是把没做到的项写成「通过」。验收表每行都必须挂证据，无法自动化的一项就写「未自动化」。
