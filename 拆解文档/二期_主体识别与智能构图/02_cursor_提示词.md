# Cursor 任务提示词（K1–K6）

> 用法：按顺序逐个任务执行。K1 可立即开始；K3 / K4 先用 mock 数据，C1–C3 完成后切换真实数据源。
> 配套约束见同目录 `00_功能拆解与分工.md`。契约唯一源：`src/core/subject/types.ts`（Claude Code 产出）。

## K1 — 图片导入 UI 增强（可立即开始）

```text

开始"主体识别与智能构图"二期的 UI 开发，本次只做 K1：图片导入 UI 增强。

【目标】在现有 features/image-import 基础上，为主体识别流程提供完整的导入体验。

【任务】
```

## K3 — 构图工作台（三栏布局 + 实时预览）

```text
延续同一项目（契约见 src/core/subject/types.ts）。本次只做 K3：构图工作台。

【任务】
1. 新建 src/features/composition-workbench/，按文档 3.1 布局：
   - 左侧：原图与主体选择（承接 K2）
   - 中间：构图预览画布（主体可拖动、滚轮 / 手柄缩放；预览用合成契约 composePreview 或
     本地轻量预览渲染，确保拖动流畅，必要时用 requestAnimationFrame 节流）
   - 右侧：参数面板——主体占比（50/60/70/80/90% 预设 + 自定义输入）、主体位置
     （居中 / 偏上 / 偏下 / 左 / 右 / 自由）、画布比例（正方形 / 竖版 / 横版）、边距开关
   - 底部：上一步、重新识别、确认生成（确认后才调用 generatePattern 契约）
2. 主体锁定：构图确认后锁定主体位置，后续调整背景不改变主体大小（文档 3.2）。
3. 参数变更实时反映到预览；参数持久化走 Composition 契约（返回编辑可恢复）。
4. 数据源策略同 K2：先 mock，C3/C6 落地后切换。
5. pnpm typecheck / lint 通过；拖动 / 缩放 / 参数联动逐项目检。

【约束】不修改 src/core/composition；状态绑定时只消费 C6 预定义的 store 切片类型。
【验收】参数变化实时更新预览；确认 / 返回编辑往返数据一致；确认后成功进入生成流程。
```

```text
【约束】透明区域在预览中不得显示为黑色；不修改 core。
```

## K5 — 手动补选 / 擦除画笔（P1）

```text
延续同一项目。本次只做 K5：蒙版手动修正画笔。

【任务】
1. 在主体选择界面（K2）叠加画笔层：
   - 补选：把区域加入前景；擦除：从前景移除
   - 笔刷大小可调；操作支持撤销（至少一步或栈式撤销）
2. 数据层：直接读改 SubjectMask 结构（C1 契约），修改后触发边界框重算（调用 C2 契约），
   并同步构图预览。
3. 触发时机：识别失败 / 主体蒙版有缺口时引导用户使用（文档第 9 章场景）。
4. pnpm typecheck / lint 通过；目检补选、擦除、撤销、bbox 重算。

【约束】画笔是简单笔刷，不做专业蒙版编辑器（二期红线）；蒙版修改走契约，不绕过存储层。
【验收】蒙版缺口可通过画笔修复并影响后续构图与生成。
```
