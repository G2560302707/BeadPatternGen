# K6 测试说明

## 覆盖点

| 状态 | 如何到达 | 断言 |
| --- | --- | --- |
| 上传中 / 解码中 | `import-phase`（上传窗口极短） | Vitest 状态机 + E2E `data-phase=detecting` |
| 处理中 | mock 识别 4 段进度 | `subject-progress` |
| 成功 | mock `ok` | `subject-candidate-mock-main` + `composition-canvas` |
| 失败 | `?mock-scenario=fail` | `subject-error[data-code=E_INFERENCE_FAILED]`，可重试 |
| 无主体 | `?mock-scenario=empty` | `E_NO_SUBJECT` + 手动框选入口 |
| 多主体 | `?mock-scenario=multi` | `subject-multi-hint`，可选 `mock-alt` |
| 预览 | 识别成功后构图台 | `composition-workbench` / `composition-canvas` |
| 重新生成 / 重新识别 | `redetect-subject` | 再次出现进度后回到成功 |
| 构图超界 | E2E hook 把 `offsetX` 拉到 0.9 | `overflow-warning`，可「采纳建议位置」 |
| 导入失败 | 8×8 PNG | `import-error[data-kind=resolution-too-low]` |
| 主路径 | 导入 → mock 识别 → 调占比/位置/网格 → 确认 → 生成 → 导出 PNG | `tests/e2e/compose.spec.ts` |
| 再导入恢复 | 同一 PNG 刷新后再导入 | 跳过分割，直接出现 `mock-main` |
| 回归 | 跳过构图走一期裁剪/生成/保存/导出 | `tests/e2e/flow.spec.ts` |

## Mock 策略

- E2E 一律 `/?mock-detection=1`，避免拉 ONNX / wasm，也避免隐私用例里的域外请求。
- 场景：`ok`（默认）/ `empty` / `fail` / `multi`，可通过 `?mock-scenario=` 或 `window.__beadMockDetect` 切换。
- `window.__beadWorkspace` 仅 mock 模式挂载，用于超界用例改构图参数。
- mock 只替换分割 runner，识别结果会写入 IndexedDB；再导入同一文件会恢复主体、跳过分割。
- 确认构图：`persistSubjectMaskInBrowser` → `composePreviewInBrowser` 保存构图记录。
- IDB 不可用时确认构图回退 `composeImage`。

## 已知限制

- 「上传中」只有 `setTimeout(0)` 一帧，Playwright 不稳定截到，以 `detecting` + 单元测试代替。
- 真实 ONNX 路径不在 E2E 覆盖（需模型文件与更长超时）；本地 `VITE_SUBJECT_DETECTION` 未设 mock 时走 Worker。
- 手动框选仍是占位入口，无拖框交互。
- 一期网格改尺寸不再清空主体切片（否则构图台改「图纸网格」会丢掉候选）。
