# S09 · 四模式参数手册（PARAMS）

> 适用文件：`types.ts` / `profiles.ts` / `refine.ts`
> 目标函数、默认值、调参顺序与危险边界都以本文件为准。
> 本模块不判断“审美对错”；它只提供**机制正确、可调、可复现**的局部优化。

---

## 1. 目标函数与单位

每一轮、每个格子只做一件事：在候选集里找比当前色得分更低的颜色。

```
score(i, j) = ΔE(cell_i, candidate_j)
            + isolatedPenalty   · I(i, j)
            + edgeProtectWeight · edgeStrength[i] · R(i, j)
```

- `I(i, j) = 1`：把颜色 `j` 放到格子 `i` 后，`i` 的 4-邻域里没有任何同色格。
- `R(i, j) = 1`：`j` 与格子当前色不同（这是一次改色）；当前色自身 `R = 0`。
- `edgeStrength[i] ∈ [0, 1]`：由 S08 / S10 的结构分析提供，不是本模块计算的。

### 1.1 ΔE 从哪里来（重要）

`RefineOptions` 只给 `perCellDelta[i] = ΔE(原始采样色, 当前色)`，**没有给原始采样色**，
因此候选色到原始色的真实 ΔE 无法精确计算。实现使用三角不等式的保守上界：

```
ΔE(原始, 候选) ≤ ΔE(原始, 当前) + ΔE(当前, 候选)
               = perCellDelta[i] + colorDelta(当前, 候选)
```

- 当前色的得分用精确值 `perCellDelta[i]`；
- 候选色用上界，**绝不低估**改色的保真度代价；
- `perCellDelta[i]` 对所有候选相同，在比较时抵消，因此**不会阻止孤立点修复**；
  即使调用方把 `perCellDelta` 全填 0，孤立点仍会被正常处理。

### 1.2 一次改色成立的条件

对孤立格（只有孤立格才可能改色）：

```
当前得分 = perCellDelta + isolatedPenalty
候选得分 = perCellDelta + ΔE(当前, 候选) + isolatedPenalty·I + edgeProtectWeight·edgeStrength
```

候选若仍造成孤立（`I = 1`），得分必然 ≥ 当前得分，不可能严格更优。因此实际比较的是：

```
ΔE(当前, 候选) + edgeProtectWeight · edgeStrength  <  isolatedPenalty
并且  ΔE(当前, 候选)  <  colorMergeThreshold（严格小于）
```

**`isolatedPenalty` 是“允许的颜色漂移预算”**；`colorMergeThreshold` 是硬上限；
`edgeProtectWeight · edgeStrength` 是边缘格额外付出的代价。

### 1.3 数值单位

所有色差类参数的单位跟随 `RefineOptions.metric`：

| metric      | 单位           | 典型范围 | 本文件的默认值是否适用 |
| ----------- | -------------- | -------- | ---------------------- |
| `ciede2000` | CIEDE2000 ΔE   | 0–100    | **是**，默认值按它标定 |
| `oklab`     | Oklab 欧氏距离 | 0–1      | 否，需乘以约 `0.01`    |

切换到 `oklab` 时，`colorMergeThreshold`、`isolatedPenalty`、`edgeProtectWeight`
都要按约 `1/100` 缩放。例如 photo 的 `5 / 6 / 3` 对应 `0.05 / 0.06 / 0.03`。
不做自动换算，避免把度量选择藏进隐式策略。

## 2. 四种模式的默认值

| 参数                     | photo |     anime |      logo | landscape |
| ------------------------ | ----: | --------: | --------: | --------: |
| `defaultDithering`       |  none |      none |      none |      none |
| `allowUserDithering`     |  true | **false** | **false** |      true |
| `edgeProtectWeight`      |     3 |         6 |         8 |       2.5 |
| `isolatedPenalty`        |     6 |         5 |         3 |         8 |
| `colorMergeThreshold`    |     5 |         4 |         2 |         6 |
| `localRefinePasses`      |     2 |         3 |         2 |         3 |
| `neighborCandidateCount` |     8 |         8 |         8 |         8 |

默认值的设计意图：

- **anime / logo 的边缘格被完全冻结**：`edgeStrength = 1` 时
  `edgeProtectWeight ≥ isolatedPenalty`，改色代价至少等于孤立惩罚，永远不会改色。
- **logo 最保守**：合并阈值 2，只允许几乎同色的合并；空格 `-1` 永远不参与优化。
- **landscape 最积极**：孤立惩罚 8 > photo 的 6，边缘权重仅 2.5，优先消除渐变杂点。
- **photo 折中**：允许修复孤立点，但五官附近 `edgeStrength` 高的格子要付出 3 ΔE 的代价。

## 3. 逐参数说明

### 3.1 `isolatedPenalty`

| 项目       | 内容                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 作用       | 孤立格改色的收益来源；唯一能**驱动**改色的权重。                                                                                               |
| 可观察效果 | 调大：更多孤立豆被并入邻近色，杂点减少，画面更“整块”。调小：孤立豆保留，细节更锐利但可能出现雪花点。`= 0` 时整个局部优化是恒等变换（见 3.7）。 |
| 默认值     | photo 6 / anime 5 / logo 3 / landscape 8                                                                                                       |
| 调整方向   | 杂点多 → 调大；眼睛高光、单豆细节消失 → 调小。                                                                                                 |
| 安全范围   | CIEDE2000 下建议 3–10；超过 15–20 进入 §5 的反例区间。                                                                                         |

### 3.2 `edgeProtectWeight`

| 项目       | 内容                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 作用       | 对“边缘格改色”额外收税；只抑制改色，不驱动改色。                                                                     |
| 可观察效果 | 调大：描边、字母、山脊保持硬边，边缘不参与合并。调小：边缘也会被平滑，轮廓变软甚至断裂。`= 0` 时边缘格与内部格同权。 |
| 默认值     | photo 3 / anime 6 / logo 8 / landscape 2.5                                                                           |
| 调整方向   | 描边被吃掉 → 调大；边缘附近出现不该有的孤立点且需要修复 → 调小。                                                     |
| 冻结条件   | `edgeProtectWeight × edgeStrength ≥ isolatedPenalty` 时，该边缘格永不改色。                                          |
| 安全范围   | 0–10；logo / anime 不要低于 `isolatedPenalty`。                                                                      |

### 3.3 `colorMergeThreshold`

| 项目       | 内容                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 作用       | 候选色的硬门槛：只有与当前色的 ΔE **严格小于**该值的色卡色才允许替换。                                                                                   |
| 可观察效果 | 调大：允许跨更大的色差合并，颜色数量下降，画面更平。调小：只合并几乎同色的色卡，细节保留但杂点可能修不掉。`= 0` 时除当前色外没有候选，优化变成恒等变换。 |
| 默认值     | photo 5 / anime 4 / logo 2 / landscape 6                                                                                                                 |
| 调整方向   | 色带 / 杂色太多 → 小幅调大（每次 +1）；高光、眼色、文字颜色被吃掉 → 调小。                                                                               |
| 安全范围   | CIEDE2000 下建议 2–6；超过 8 极易吃掉眼睛高光与动漫色块边界。                                                                                            |

### 3.4 `localRefinePasses`

| 项目           | 内容                                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 作用           | 常规 row-major 扫描的轮数；`0` 完全关闭局部优化。                                                                                                                                           |
| 可观察效果     | `0`：输出逐格等于输入。`≥ 1`：启用优化，至少扫描该轮数；若最后一轮仍有变化，函数会继续稳定化扫描直到某一轮零变化。**因此 `≥ 1` 的最终结果相同**，调大不会让画面更平滑，只会增加下限工作量。 |
| 默认值         | photo 2 / anime 3 / logo 2 / landscape 3                                                                                                                                                    |
| 调整方向       | 只用于“0 = 关闭 / ≥ 1 = 开启”；开启时保持 2–3。不要指望调大来增强效果。                                                                                                                     |
| 为什么这样实现 | “连续两次调用结果相同”是硬要求。只跑固定轮数时，向上 / 向左传播的长链可能在下一轮继续变化；稳定化扫描用严格的单调性证明（每次改色都减少孤立格数）保证返回值是不动点。                       |

### 3.5 `neighborCandidateCount`

| 项目       | 内容                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 作用       | 每个格子参与比较的“当前色最近邻”数量上限（当前色总会保留）。                                                                       |
| 可观察效果 | 调大：候选集包含更多较远的色卡色，更容易找到与邻格同色的合并目标。调小：只考虑最接近的几种颜色，可能找不到邻格颜色而修不掉孤立点。 |
| 默认值     | 8（四个模式一致）                                                                                                                  |
| 调整方向   | 确认某格本应能并入邻色却没动 → 先检查该邻色是否在候选集，再考虑 +4；不要无基准地加到几十。                                         |
| 安全范围   | 1–16；超过 16 时 `colorMergeThreshold` 必须同步收紧。                                                                              |

### 3.6 `defaultDithering` / `allowUserDithering`

| 项目       | 内容                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- |
| 作用       | 规格 4.4 的策略标志，供 S10 / S12 决定默认值与 UI 开关；`refineLocally` 不读取它们。                                    |
| 可观察效果 | `defaultDithering` 一律 `none`，生成结果默认无抖动。`allowUserDithering=false` 时 UI 必须禁用抖动开关（anime / logo）。 |
| 默认值     | 四个模式都是 `none`；photo / landscape 允许开启，anime / logo 强制关闭。                                                |
| 调整方向   | 不要调。这是规格硬约束，不是调参项。                                                                                    |

### 3.7 参数之间的关键关系

- **只有 `isolatedPenalty > 0` 才会发生改色。** 其余权重都是惩罚或门槛；
  `isolatedPenalty = 0` 时即使 `edgeProtectWeight`、`colorMergeThreshold`、
  `neighborCandidateCount` 都很大，输出仍逐格等于输入。
- `colorMergeThreshold = 0` 同样使优化变成恒等变换（严格 `< 0` 无候选）。
- `edgeProtectWeight` 只能把改色“压住”，不能把格子“推去”某个颜色。
- `neighborCandidateCount` 只扩大候选集；最终选谁仍由目标函数决定。

## 4. 建议调参顺序

1. **锁定不变量**：固定 metric、色卡、网格尺寸、采样与抖动设置。不要在不同图片之间
   比较不同参数。
2. **先关掉局部优化**：`isolatedPenalty = 0`、`edgeProtectWeight = 0`
   （或 `localRefinePasses = 0`），确认输出就是纯量化结果，作为基线。
3. **定 `colorMergeThreshold`**：测量“必须保持区分”的最小色差（例如眼白 vs 虹膜、
   高光 vs 皮肤、logo 主色 vs 背景），把阈值设在该值之下。CIEDE2000 从 2–5 起步。
4. **加 `isolatedPenalty`**：从 4 开始逐步调大，直到孤立豆数量明显下降；一旦眼睛高光、
   单豆装饰或文字开始消失就回退。推荐 4–10。
5. **加 `edgeProtectWeight`**：从 2 开始；anime / logo 调到 ≥ `isolatedPenalty`
   （保证 `edgeStrength=1` 的格子完全冻结）。photo / landscape 保持较弱保护。
6. **最后才动 `neighborCandidateCount`**：只有确认“邻格颜色不在候选集”时才加，
   每次 +4，并重新检查 `colorMergeThreshold`。
7. **`localRefinePasses` 放最后**：只决定 0 / ≥ 1；开启时保持 2–3。
8. **固定基准图回归**：至少四类图各一张——人像（眼睛高光）、动漫（描边 + 色块）、
   logo（小字 / 透明背景）、风景（大面积渐变）。同时看孤立豆数量、细线诊断和
   实际使用色数，不能只看“看起来更干净”。

## 5. 哪些参数不要动 / 危险边界

### 5.1 不要为了让画面“更干净”而无脑调大 `colorMergeThreshold`

CIEDE2000 超过 8 时，皮肤、头发、眼睛高光之间的色差都可能落进阈值。
最典型的后果：

- 眼睛里的单豆白色高光被合并成虹膜色，眼神变平；
- 动漫的两种相近发色 / 阴影色被并成一块，色块边界消失；
- logo 的深浅两版主色被并成一种，品牌色失真；
- 高光与背景之间的过渡带被整体抬亮或压暗。

`colorMergeThreshold` 是最后一道保真度闸门；`isolatedPenalty` 再大也不能突破它。

### 5.2 不要把 `edgeProtectWeight` 调到 0（anime / logo）

`edgeProtectWeight = 0` 时，边缘格与内部格同权，硬边会被当成普通孤立点处理。
anime 的描边、logo 的字母和直角会被磨圆或直接并入背景。anime / logo 的安全前提是：

```
edgeProtectWeight × edgeStrength ≥ isolatedPenalty
```

在 `edgeStrength = 1` 的格子上，这条不等式必须成立。

### 5.3 不要无基准地把 `neighborCandidateCount` 加到几十

候选集变大后，原本“太远、不该考虑”的颜色也会进入比较。如果同时把
`colorMergeThreshold` 放得很宽，格子可能跳到色相相近但明度/饱和度差异明显的颜色，
产生肉眼可见的色块跳变。保持 8；确有需要时一次 +4 并做基准图对比。

### 5.4 不要把 `localRefinePasses` 当成“平滑强度”

`≥ 1` 的结果都会稳定化到同一个不动点（见 3.4）。调大只增加 CPU 时间，
不会增加平滑程度。想要更强/更弱的优化，请调 `isolatedPenalty` /
`colorMergeThreshold`，不要调轮数。

### 5.5 不要给 `perCellDelta` 传错语义

它必须是 **ΔE(原始采样色, 当前色)**。如果上游误传“当前色到候选色的 ΔE”或
“原始色到最近邻的 ΔE”，本模块的保真度上界会失真：过小会低估改色代价，
过大则会让所有候选的保真度项一起抬高（虽然候选间仍抵消，但诊断与调试会误导）。
空格没有采样色，可以填 0 或任意有限哨兵值；非空格必须是有限非负数。

## 6. 反例：把 `isolatedPenalty` 调到极大

假设 CIEDE2000、`colorMergeThreshold = 6`、`edgeProtectWeight = 0`，
把 `isolatedPenalty` 从 6 一路调到 1000。

### 6.1 机制

对孤立格：

```
当前得分 = perCellDelta + 1000
候选得分 = perCellDelta + ΔE(当前, 候选) + 0
```

只要候选能消除孤立，且 `ΔE(当前, 候选) < 6`，候选得分就远低于当前得分。
`isolatedPenalty` 实际上变成了“无限预算”：**颜色漂移的代价被忽略**，
唯一约束只剩 `colorMergeThreshold = 6`。于是任何孤立格都会被并入
4-邻域里某个 ΔE < 6 的邻色，不管这个邻色是不是它原本想要的颜色。

### 6.2 画面会发生什么

1. **斜线与点状细节断裂**：一条 45° 的 1 像素细线，每个珠子在 4-邻域里
   只有背景（对角格不算 4-邻域），因此每个珠子都是孤立格。它们会逐颗
   被背景色吸收，细线断成虚线，再断成孤立点，最终整条消失。
   （水平/垂直细线因为左右或上下有同色邻居，反而不受影响——这解释了
   “为什么只有斜线断”的视觉不对称。）
2. **眼睛高光消失**：虹膜上的单颗白色高光 4-邻域全是虹膜色，是孤立格；
   它会被并入虹膜色，眼睛失去反光，显得空洞、发灰。
3. **logo 小字糊掉**：单珠宽的笔画端点、字母内部的孤立转折会被背景或
   相邻笔画颜色吃掉；笔画变粗、粘连，小字不可读。
4. **大面积区域变“糊”**：渐变中的杂点全部被最近的邻色吸收，色带边界
   向四周扩张，云、皮肤、头发的过渡变得块状；同时实际色数下降，
   但下降的是**必要的细节色**，不是噪点。
5. **颜色数量统计失真**：优化后色数变少会让“更省豆子”看起来像优点，
   但被省掉的是高光、描边等关键结构。必须结合孤立豆诊断与细线诊断一起看。

### 6.3 正确的做法

- 把 `isolatedPenalty` 停在“孤立豆明显减少、但眼睛高光/斜线/小字仍在”的位置；
- 对 logo / anime，保持 `edgeProtectWeight ≥ isolatedPenalty`，用边缘权重冻结
  关键结构；
- 不要用极大的 `isolatedPenalty` + 很宽的 `colorMergeThreshold` 组合；
  两者叠加等于“允许任何颜色替换任何孤立格”。

## 7. 实现层不变量（调参时可以直接依赖）

1. **非孤立格永不改色**：当前得分是 `perCellDelta`，任何候选都要再加上
   非负的色差与边缘惩罚，不可能严格更优。
2. **改色只发生在“孤立 → 非孤立”**：候选若仍造成孤立，得分必然不低于当前得分。
3. **不会产生新的孤立格**：改色格原本孤立 ⇒ 它没有同色邻格 ⇒ 邻格没有依赖它
   维持同色相邻。因此孤立格数量单调下降，算法必然收敛。
4. **幂等**：返回值是不动点；把它再次作为输入，第一轮扫描就零变化。
5. **确定性**：row-major 扫描、邻域顺序 左→右→上→下、候选按 (距离, 下标) 全序、
   严格 `<` 才接受、平局保留当前色；无随机数 / 时间 / Map 遍历顺序。
6. **输入不可变**：`cells`、`perCellDelta`、`edgeStrength`、`palette`、
   `profile` 都只读；返回值是新分配的 `Int16Array`。
7. **空格 `-1` 永远保持 `-1`**：不参与优化，也不会被候选色填充。
8. **权重全 0**（`isolatedPenalty = 0` 且 `edgeProtectWeight = 0`）时，
   输出逐格严格等于输入。

## 8. 速查：症状 → 先调哪个参数

| 症状                    | 首选                                         | 次选                                      | 禁止                                            |
| ----------------------- | -------------------------------------------- | ----------------------------------------- | ----------------------------------------------- |
| 渐变里全是单颗杂点      | `isolatedPenalty` ↑                          | `colorMergeThreshold` ↑（小幅）           | 直接把 `isolatedPenalty` 拉到 20+               |
| 眼睛高光 / 单豆装饰消失 | `isolatedPenalty` ↓                          | `colorMergeThreshold` ↓                   | 继续调大孤立惩罚                                |
| 动漫描边被吃掉          | `edgeProtectWeight` ↑                        | `colorMergeThreshold` ↓                   | 把边缘权重设为 0                                |
| logo 小字粘连           | `edgeProtectWeight` ↑                        | `colorMergeThreshold` ↓                   | 调大 `isolatedPenalty`                          |
| 某格应该并入邻色但没动  | 检查候选集：`neighborCandidateCount` ↑（+4） | 检查 `colorMergeThreshold` 是否小于该色差 | 盲目把阈值调到 20                               |
| 颜色数量过多、画面花    | `colorMergeThreshold` ↑（每次 +1）           | `isolatedPenalty` ↑                       | 一次性把阈值翻倍                                |
| 想完全关闭局部优化      | `localRefinePasses = 0`                      | `isolatedPenalty = 0`                     | 只把 `edgeProtectWeight` 设为 0（不会关闭改色） |
