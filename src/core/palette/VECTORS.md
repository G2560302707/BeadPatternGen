# S05 · 色卡索引与最近邻匹配 —— 测试向量与推导

本文所有“实测”数值都由 `src/core/palette/palette.test.ts` 中的实现直接运行得到；
手算值与实测值的差异只来自十进制书写精度。距离单位为对应色彩空间的自然单位：
Oklab 为欧氏距离（无量纲），CIEDE2000 为 ΔE00。

## 0. 输入策略、错误码与校验顺序

### 0.1 策略：抛错，不静默兜底

| 输入                                  | 行为                                                |
| ------------------------------------- | --------------------------------------------------- |
| RGB 任一通道非有限数                  | 抛 `PaletteError`，code = `INVALID_SAMPLE`          |
| RGB 任一通道不在 [0, 255]             | 抛 `PaletteError`，code = `INVALID_SAMPLE`          |
| palette 为空                          | 抛 `PaletteError`，code = `EMPTY_PALETTE`           |
| palette 条目字段缺失 / 类型错误       | 抛 `PaletteError`，code = `INVALID_PALETTE_ENTRY`   |
| 条目 hex 不能被 `hexToRgb` 解析       | 抛 `PaletteError`，code = `INVALID_HEX`             |
| 同一色卡内 code 重复                  | 抛 `PaletteError`，code = `DUPLICATE_CODE`          |
| metric 不是 `"ciede2000"` / `"oklab"` | 抛 `PaletteError`，code = `INVALID_METRIC`          |
| samples 非数组或为空                  | 抛 `PaletteError`，code = `EMPTY_SAMPLES`           |
| maxColors 不是正整数                  | 抛 `PaletteError`，code = `INVALID_MAX_COLORS`      |
| candidates 为空数组 / 非数组          | 抛 `PaletteError`，code = `INVALID_CANDIDATES`      |
| candidates 含非整数或越界下标         | 抛 `PaletteError`，code = `INVALID_CANDIDATE_INDEX` |

`PaletteError` 的定义：

```ts
class PaletteError extends Error {
  readonly code: PaletteErrorCode; // 上表第二列
}
```

错误消息同时包含定位信息：色卡下标、色号 code、原始 hex、样本下标或候选下标。
例如重复 code 的消息为
`duplicate palette code "S01" at indices 0 and 1`。

### 0.2 固定校验顺序

`buildPaletteIndex` / `indexPalette`：

1. `metric`；
2. `palette` 是数组且非空；
3. 按下标 `0..n-1` 升序逐条校验：字段类型 → code 唯一性 → hex 可解析性。

`selectPaletteSubset`：

1. `maxColors`（正整数）；
2. `metric` + `palette`（复用 `indexPalette` 的全部校验）；
3. `samples`（非空数组、每个 RGB 合法）；
4. 若 `maxColors >= palette.length`，直接返回 `[0, 1, …, n-1]`。

因此 `selectPaletteSubset([], [], 0, "oklab")` 报 `INVALID_MAX_COLORS`，
而不是 `EMPTY_PALETTE` 或 `EMPTY_SAMPLES`；该顺序由测试固定。

`nearest` 的校验顺序：查询色 → 整个 candidates 数组 → 才开始扫描。
非法候选即使排在合法候选之后，也一定抛错，不会先返回一个“看起来有效”的结果。

## 1. 3 色极小色卡：最近邻结果与手算

### 1.1 色卡

| index | code | hex       | 实测 Oklab (L, a, b)                    |
| ----: | ---- | --------- | --------------------------------------- |
|     0 | A    | `#000000` | `(0, 0, 0)`                             |
|     1 | B    | `#808080` | `(0.5998708017, 4.8561e-11, 2.2360e-8)` |
|     2 | C    | `#FFFFFF` | `(0.9999999935, 8.0953e-11, 3.7274e-8)` |

metric = `"oklab"`。

### 1.2 灰度色为什么可以手算

sRGB 解码（IEC 61966-2-1:1999）：

```text
c = c8 / 255
c_lin = ((c + 0.055) / 1.055) ^ 2.4        (c > 0.04045)
```

Oklab 的第一段是线性 sRGB → LMS 的矩阵 `M1`（Ottosson 2020），
其每一行系数之和为 1；因此等通道灰度的三个 LMS 分量都等于 `c_lin`。
第二段矩阵 `M2` 的第一行系数之和为 `0.9999999935`，后两行之和为 0。
于是灰度色的 Oklab 为：

```text
L = 0.9999999935 · cbrt(c_lin)
a ≈ 0, b ≈ 0        （只剩十进制约 1e-8 的系数截断残差）
```

逐色计算：

| hex       |  c8 | c_lin = ((c8/255+0.055)/1.055)^2.4 |  cbrt(c_lin) |
| --------- | --: | ---------------------------------: | -----------: |
| `#000000` |   0 |                                  0 |            0 |
| `#202020` |  32 |                           0.014443 |     0.243535 |
| `#404040` |  64 |                           0.051269 |     0.371495 |
| `#808080` | 128 |                           0.215860 |     0.599871 |
| `#C0C0C0` | 192 |                           0.527113 |     0.807796 |
| `#FFFFFF` | 255 |                                  1 | 0.9999999935 |

### 1.3 查询与距离

查询色 `#404040` 的逐步手算：

```text
c = 64/255 = 0.2509804
c_lin = ((0.2509804 + 0.055) / 1.055)^2.4
      = (0.2900288)^2.4
      = 0.0512695
L = 0.9999999935 · cbrt(0.0512695)
  = 0.9999999935 · 0.3714949
  = 0.3714949

d(黑)  = |0.3714949 − 0|          = 0.3714949
d(灰)  = |0.5998708 − 0.3714949|  = 0.2283759
d(白)  = |0.99999999 − 0.3714949| = 0.6285050
```

a、b 的贡献量级为 `(1e-8)^2 ≈ 1e-16`，对 9 位小数没有影响。
最小距离是 0.2283759，对应 index 1（灰色）。

完整表格（距离保留 9 位小数；“实测”由实现输出）：

| 查询      |  到 index 0 |  到 index 1 |  到 index 2 | 最近 index |    实测距离 |    手算距离 | 绝对差 |
| --------- | ----------: | ----------: | ----------: | ---------: | ----------: | ----------: | -----: |
| `#202020` | 0.243534741 | 0.356336061 | 0.756465253 |          0 | 0.243534741 | 0.243534741 | < 1e-9 |
| `#404040` | 0.371494944 | 0.228375858 | 0.628505050 |          1 | 0.228375858 | 0.228375858 | < 1e-9 |
| `#808080` | 0.599870802 |           0 | 0.400129192 |          1 |           0 |           0 |      0 |
| `#C0C0C0` | 0.807796233 | 0.207925431 | 0.192203761 |          2 | 0.192203761 | 0.192203761 | < 1e-9 |

### 1.4 candidates 子集

查询 `#808080`：

| candidates  | 候选距离                                 | 返回 index |
| ----------- | ---------------------------------------- | ---------: |
| 未给出      | `{0: 0.599870802, 1: 0, 2: 0.400129192}` |          1 |
| `[0, 2]`    | `{0: 0.599870802, 2: 0.400129192}`       |          2 |
| `[0]`       | `{0: 0.599870802}`                       |          0 |
| `[2, 2, 0]` | `{2: 0.400129192, 0: 0.599870802}`       |          2 |

### 1.5 metric 切换的可见差异

同一查询 `#404040`，同一张 3 色色卡：

| metric      |   到 index 0 |   到 index 1 |   到 index 2 | 最近 index |
| ----------- | -----------: | -----------: | -----------: | ---------: |
| `oklab`     |  0.371494944 |  0.228375858 |  0.628505050 |          1 |
| `ciede2000` | 17.561989500 | 23.412712612 | 61.114136229 |          0 |

CIEDE2000 的明度权重 `S_L` 在 `L̄′ = 50` 附近显著大于 1：

```text
S_L = 1 + 0.015 · (L̄′ − 50)^2 / sqrt(20 + (L̄′ − 50)^2)

黑 ↔ #404040：L̄′ = 13.55，L̄′ − 50 = −36.45，S_L ≈ 1.543
灰 ↔ #404040：L̄′ = 40.34，L̄′ − 50 = −9.66， S_L ≈ 1.132
```

于是明度项分别约为 27.09 / 1.543 = 17.56 与 26.49 / 1.132 = 23.41；
前者更小，因此 CIEDE2000 判给黑色。
这证明索引层确实按 metric 选择了对应色彩空间与距离函数，而不是“先算 Lab 再统一比较”。

## 2. 平局构造与“较小 index 胜”的证明

### 2.1 构造

| index | code | hex       | 解析后的 RGB    |
| ----: | ---- | --------- | --------------- |
|     0 | A    | `#000000` | (0, 0, 0)       |
|     1 | B    | `#808080` | (128, 128, 128) |
|     2 | C    | `#000`    | (0, 0, 0)       |

查询 `#101010`。index 0 与 index 2 是同一实测色的两种合法 hex 写法。
在真实色卡中，不同色号共用同一实测 hex 也是允许的；本模块只禁止重复 `code`。

### 2.2 距离逐位相等

构建时对两条记录分别执行同一个纯函数 `hexToRgb` → `rgbToOklab`：

```text
hexToRgb("#000000") = { r: 0, g: 0, b: 0 }
hexToRgb("#000")    = { r: 0, g: 0, b: 0 }   // 短写展开 0→00
```

两次输入的 RGB 对象逐字段相同，`rgbToOklab` 的运算序列完全相同，
因此缓存的两个 `SpacePoint` 逐位相同；查询点相同时，
`deltaEOklab(query, point0)` 与 `deltaEOklab(query, point2)` 也逐位相同：

```text
d(0) = d(2) = 0.17304230759282468
d(1) = 0.426828494114293        // 灰色更远
```

### 2.3 选择证明

比较函数（`index-builder.ts` 的 `isBetterCandidate`）：

```ts
distance < bestDistance ||
  (distance === bestDistance && (bestIndex === NO_MATCH_INDEX || index < bestIndex));
```

**全表扫描**（候选顺序 0, 1, 2）：

1. index 0：`0.173… < +∞` → best = (0, 0.173…)。
2. index 1：`0.426… < 0.173…` 为假 → 不替换。
3. index 2：`0.173… < 0.173…` 为假；第二项 `0.173… === 0.173…` 为真，
   但 `2 < 0` 为假 → 不替换。

结果 `{ index: 0, distance: 0.17304230759282468 }`。

**乱序候选** `[2, 0]`：

1. index 2：`0.173… < +∞` → best = (2, 0.173…)。
2. index 0：第一项为假；第二项为真且 `0 < 2` 为真 → 替换为 (0, 0.173…)。

结果同样是 index 0。这说明平局规则不是“先到先得”，而是与候选顺序无关的
“较小 index 胜”。测试对 `[0,1,2]`、`[2,0]`、`[2]` 三种输入分别断言。

### 2.4 为什么不用 epsilon

若使用 `distance <= bestDistance + EPS`，平局集合会随 `EPS` 改变，
“谁更小”将依赖一个没有标准来源的魔数；不同平台上的末位误差也可能让结果漂移。
本模块要求的是**字节级完全相等**（`===`），平局定义唯一，输出唯一。

8 位量化使两个不同颜色的几何距离几乎不可能逐位相等；因此用“同一 RGB 的两种
hex 写法”构造精确平局。它检验的正是规格要求的相等分支，而非浮点近似。

## 3. selectPaletteSubset：10 色色卡 + maxColors = 4

> **1.2 变更**：选色算法从「加权 k-medoids（覆盖贪心）」换成
> 「确定性 k-means 聚类 → 真实色卡映射」。§3.3–§3.7 的逐步推导记录的是旧
> 算法的历史向量，当前实现不再逐步复现它；测试改为断言不变量
> （子集 ⊆ 色卡、长度 = min(maxColors, size)、升序无重复、确定性、
> maxColors=1 时覆盖权重最大者）。
>
> 换算法的原因：旧贪心按「覆盖权重 × 距离」挑色卡色，大色块永远先占坑，
> 眼睛、腮红、小饰物这类**样本少但色距远**的簇排不进 maxColors——小尺寸
> 图纸上五官直接消失。k-means 让每个足够密或足够远的簇都有自己的中心，
> 中心再映射到最近的真实色卡色；聚类中心是合成色，只用于挑色卡，绝不出现在
> 任何输出里。
>
> 当前算法（完全确定，无随机数）：
> 1. 样本按精确 RGB 折叠，weight = 出现次数；
> 2. 最远点确定性初始化：第一个中心 = 权重最大样本，之后取
>    `weight × minDistance` 最大者，共 k 个；
> 3. Lloyd 迭代（≤ 32 轮或零换簇）：最近中心分配 + 加权均值更新，
>    空簇用 `weight × minDistance` 最大样本补位；**k = 1 时跳过 Lloyd**，
>    保留「覆盖权重最大者」的旧契约（黑白图 maxColors=1 不会选成灰豆）；
> 4. 每个中心映射到全色卡最近色，按簇权重降序去重；
> 5. 不足 k 个时按旧贪心分数补齐，仍不足按色卡下标补齐，长度严格等于
>    min(maxColors, palette.length)，输出升序。

## 4. 确定性、具名常量与复杂度

### 4.1 具名常量及来源

| 常量                    |  值 | 位置               | 来源                          |
| ----------------------- | --: | ------------------ | ----------------------------- |
| `SAMPLE_CHANNEL_MIN`    |   0 | `types.ts`         | IEC 61966-2-1:1999 8 位量化域 |
| `SAMPLE_CHANNEL_MAX`    | 255 | `types.ts`         | IEC 61966-2-1:1999 8 位量化域 |
| `NO_MATCH_INDEX`        |  −1 | `index-builder.ts` | 内部哨兵；不参与数值比较      |
| `INITIAL_BEST_DISTANCE` |  +∞ | `index-builder.ts` | 任何有限距离都会替换          |
| `NO_INDEX`              |  −1 | `subset.ts`        | 内部哨兵                      |
| `INITIAL_BEST_SCORE`    |  −1 | `subset.ts`        | score 非负，任何候选都会替换  |

色彩空间矩阵、D65 白点、CIEDE2000 的全部系数都不在本模块重复定义；
它们唯一存在于 S04 的具名常量中，本模块通过 `../color` 调用。
本模块不使用 epsilon、不使用百分比容差。

### 4.2 固定求值顺序

- 色卡转换：`palette[0] → palette[n-1]`，转换后按同一顺序存入数组。
- 样本折叠：相同 RGB 的出现次数累加；之后按 `(r, g, b)` 字典序排序，
  Map 的插入顺序不会影响任何求和或比较。
- 距离求和：固定为 `ΔL² + Δa² + Δb²` 的左结合顺序（由 S04 的
  `deltaEOklab` 保证）；CIEDE2000 的项顺序同样由 S04 固定。
- subset 打分：每轮按唯一样本下标 `0..u-1` 升序扫描；每个 score 是一次
  `weight × minDistance` 乘法，不存在多项累加；精确平局再按对应色卡色
  index 比较。
- 所有 argmax / 最近邻扫描都按下标升序，并使用严格 `<` / `>`；
  平局天然保留更小 index。

### 4.3 禁止项检查

| 禁止项                                           | 结果                                          |
| ------------------------------------------------ | --------------------------------------------- |
| `Math.random`                                    | 0 处                                          |
| `Date.now` / `performance.now`                   | 0 处                                          |
| `window` / `document` / `fetch` / `localStorage` | 0 处                                          |
| 不稳定的 `sort` 比较器                           | 无：RGB 字典序与整数升序都是严格全序          |
| 依赖 Map/Set 遍历顺序                            | 无：Map 仅做计数与成员判断，输出前已排序      |
| 跨调用可变状态                                   | 无：索引对象字段全部 `readonly`，构建后无写入 |

### 4.4 复杂度

| 操作                  | 时间         | 空间     | 说明                            |
| --------------------- | ------------ | -------- | ------------------------------- |
| `buildPaletteIndex`   | O(n)         | O(n)     | n 次 hex 解析 + 色彩空间转换    |
| `nearest`（无候选）   | O(n)         | O(1)     | 查询转换一次，扫描 n 个缓存点   |
| `nearest`（k 个候选） | O(k)         | O(1)     | 候选先整体校验                  |
| `selectPaletteSubset` | O(u·n + k·u) | O(u + n) | u = 唯一 RGB 数，k = 实际选色数 |

n ≤ 500 时，`nearest` 最多做 500 次色差计算，不需要 KD-tree。
更重要的是：CIEDE2000 不是严格度量，存在违反三角不等式的已知例子，
依赖“下界剪枝”的空间树可能漏掉真正的最近邻；线性扫描是正确性优先的选择。
candidates 参数已经覆盖了抖动 / 局部优化需要的“只在候选集中查”的场景。
