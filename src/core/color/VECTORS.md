本文件中的所有“本实现输出”均由 `src/core/color/color.test.ts` 同一份源码在
Node 22.22.0 / Vitest 5.0.5 下实际运行得到，不是手算或第三方库结果。

## 0. 输入域策略（全包唯一策略：抛错）

| 输入 | 合法域 | 越界 / 非有限时的行为 |
| --- | --- | --- |
| `RGB.r/g/b` | 有限数，`[0, 255]` | 抛 `RangeError` |
| `srgbToLinear(c)` / `linearToSrgb(c)` | 有限数，`[0, 1]` | 抛 `RangeError` |
| `Lab.L/a/b` | 有限数（量纲不设限） | `NaN` / `±Infinity` 抛 `RangeError` |
| `Oklab.L/a/b` | 有限数（量纲不设限） | `NaN` / `±Infinity` 抛 `RangeError` |
| `hexToRgb(hex)` 的 `hex` | 匹配 `^#[0-9a-fA-F]{3}$` 或 `^#[0-9a-fA-F]{6}$` | 抛 `RangeError` |
| `rgbToHex(rgb)` | 同 `RGB` 合法域 | 抛 `RangeError` |

选择“抛错”而非“输入 clamp”的理由：S04 是流水线地基，静默 clamp 会把上游的
采样、解码、调色板数据错误伪装成合法颜色。输出侧的 `labToRgb` /
`oklabToRgb` 仍按规格对 **结果 RGB** 做 clamp + 四舍五入；两者不矛盾。

`labToRgb` / `oklabToRgb` 对有限但极端的 Lab/Oklab 输入，先把线性 RGB
饱和到 `[0,1]`，再做 sRGB 编码、乘 255、`Math.round`、最终饱和到 `[0,255]`。
`clampToUnit` 把 `NaN` 映射为 0、`+Infinity` 映射为 1、`-Infinity` 映射为 0，
因此极端外推输入也有确定结果。

| 输入 | 预期行为 | 本实现输出 |
| --- | --- | --- |
| `{r:170, g:187, b:204}` | 大写、两位补齐 | `"#AABBCC"` |

## 4. 常量、来源与浮点求值顺序

### 4.1 sRGB 传递函数（IEC 61966-2-1:1999 §6.5）

`12.92`、`1.055`、`0.055`、`2.4`、编码阈值 `0.04045`、线性阈值 `0.0031308`，
分别对应 `SRGB_LINEAR_SEGMENT_SLOPE`、`SRGB_GAMMA_SCALE`、`SRGB_GAMMA_OFFSET`、
`SRGB_GAMMA_EXPONENT`、`SRGB_ENCODED_THRESHOLD`、`SRGB_LINEAR_THRESHOLD`。
`srgbToLinear(0.5) = 0.21404114048223255`，测试断言 12 位小数。

注意：`0.04045 / 12.92 = 0.0031308049535603713` 略大于 `0.0031308`，
因此 `linearToSrgb(srgbToLinear(0.04045))` 与 `0.04045` 相差约
`2.96e-8`。这是两个公开常数各自四舍五入造成的标准不连续，测试容差为 `1e-6`。

### 4.2 XYZ 与 Lab

- D65 白点：`X_n = 0.95047`、`Y_n = 1.0`、`Z_n = 1.08883`
  （CIE 15:2004；由 sRGB 白点 x=0.3127, y=0.3290 推出）。
- Lab 分段常数：`ε = 216/24389 = 0.008856451679035631`、
  `κ = 24389/27 = 903.2962962962963`（CIE 15:2004 精确有理数）。
- 线性 sRGB → XYZ（D65）：
  `[[0.4124564, 0.3575761, 0.1804375], [0.2126729, 0.7151522, 0.0721750],
  [0.0193339, 0.1191920, 0.9503041]]`（IEC 61966-2-1 / Lindbloom）。
- XYZ → 线性 sRGB：上式逆矩阵，`[[3.2404542, −1.5371385, −0.4985314],
  [−0.9692660, 1.8760108, 0.0415560], [0.0556434, −0.2040259, 1.0572252]]`。

### 4.3 Oklab（Ottosson 2020）

M1（线性 sRGB → LMS）、M2（LMS 立方根 → Oklab）、M2⁻¹、M1⁻¹ 均为
Ottosson 原文系数，逐项列在 `oklab.ts` 的只读矩阵常量中。
立方根用 `Math.cbrt`；逆变换的立方用 `t*t*t`（左结合），不用 `Math.pow`，
以保证跨引擎位级一致。

### 4.4 CIEDE2000（CIE 142-2001 / Sharma 等 2005）

- `kL = kC = kH = 1`；`25⁷ = 6103515625`。
- `G = 0.5·(1 − √(C̄*⁷/(C̄*⁷ + 25⁷)))`。
- `T = 1 − 0.17 cos(h̄′−30°) + 0.24 cos(2h̄′) + 0.32 cos(3h̄′+6°)
  − 0.20 cos(4h̄′−63°)`。
- `S_L = 1 + 0.015(L̄′−50)² / √(20 + (L̄′−50)²)`；
  `S_C = 1 + 0.045C̄′`；`S_H = 1 + 0.015C̄′T`。
- `Δθ = 30°·exp(−((h̄′−275°)/25°)²)`；
  `R_C = 2√(C̄′⁷/(C̄′⁷+25⁷))`；`R_T = −sin(2Δθ)·R_C`。
- 合成：`√(t_L² + t_C² + t_H² + R_T·t_C·t_H)`，其中
  `t_L = ΔL′/(k_L S_L)`、`t_C = ΔC′/(k_C S_C)`、`t_H = ΔH′/(k_H S_H)`。

### 4.5 求值顺序（写死，避免末位回归漂移）

1. 3×3 矩阵乘法固定为左结合：`((m00·v0 + m01·v1) + m02·v2)`。
2. Lab 输出固定为 `L = 116·fy − 16`、`a = 500·(fx − fy)`、
   `b = 200·(fy − fz)`。
3. Oklab 正变换顺序固定为 `线性 sRGB → M1 → cbrt → M2`；
   逆变换固定为 `M2⁻¹ → t³ → M1⁻¹`。
4. ΔE00 的平方和固定按 `t_L² → +t_C² → +t_H² → +R_T·t_C·t_H` 累加。
5. 所有函数无跨调用缓存、无模块级可变状态；矩阵与系数均为只读常量。
